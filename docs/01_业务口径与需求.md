# 业务口径与需求

## 1. 分析粒度

MVP 的最小分析对象为：

```text
物料 material_id × 仓库 warehouse_id × 分析日期 as_of_date
```

不允许只按物料汇总后直接归因，因为同一物料在不同仓库可能同时处于短缺和呆滞状态。

## 2. 术语

| 术语     | 项目定义                       |
| ------ | -------------------------- |
| 当前库存   | 截至分析日期，已过账入库减已过账出库后的在手数量   |
| 有效消耗   | 销售出库、生产领料等实际消耗；调拨和盘点默认不算消耗 |
| 无消耗天数  | 分析日期减最近一次有效消耗日期            |
| 平均日消耗  | 观察窗口内有效消耗量 / 观察窗口天数        |
| 库存覆盖天数 | 当前库存 / 平均日消耗               |
| 呆滞金额   | 被判定为呆滞的数量 × 单位成本           |
| 候选根因   | 被规则证据支持的解释，不等同于业务人员最终确认原因  |


“慢动、无动、过剩、报废/淘汰”不是同义词。MVP 先识别风险并给出候选根因，不代替财务减值或实物报废认定。

## 3. 默认判定规则

首版默认参数仅用于合成数据和可复现测试，进入真实业务前必须重新确认。

| 参数 | 默认值 | 说明 |
|---|---:|---|
| `analysis_window_days` | 90 | 平均消耗观察窗口 |
| `slow_moving_days` | 90 | 慢动风险阈值 |
| `non_moving_days` | 180 | 无动风险阈值 |
| `coverage_days_threshold` | 120 | 高覆盖风险阈值 |
| `demand_drop_ratio` | 0.40 | 近窗较前窗下降 40% |
| `purchase_excess_days` | 120 | 未消耗采购量对应覆盖天数 |
| `production_delay_days` | 14 | 生产延期阈值 |
| `new_material_protection_days` | 30 | 从首次入库日开始的新物料观察期 |

以上默认值只用于合成数据 MVP v0.2 和可复现测试，不代表行业或任何企业的统一标准。单位成本统一使用 Material 上的合成标准成本，并以 `Decimal` 表达；真实接入时再确认移动平均、批次或其他成本口径。

**决策记录（2026-08-09）**：接受以上默认值作为合成数据 MVP v0.2 的实现与测试基线。所有参数继续通过 `AnalysisThresholds` 集中配置；进入任何真实企业场景前必须重新完成业务确认，不沿用本项目默认值。

基础风险必须同时满足：

```text
current_stock > 0
AND days_without_consumption >= slow_moving_days
AND (average_daily_consumption = 0 OR coverage_days >= coverage_days_threshold)
```

风险分级：

- `NORMAL`：未满足慢动条件。
- `SLOW_MOVING`：达到慢动阈值，但未达到无动阈值。
- `NON_MOVING`：达到无动阈值，且观察窗口无有效消耗。
- `DATA_QUALITY_BLOCKED`：关键数据缺失或矛盾，禁止给出业务结论。

## 4. 边界处理

| 情况 | 处理规则 |
|---|---|
| 当前库存为 0 | 不计为当前呆滞库存，仍可查询历史 |
| 当前库存为负 | 数据质量错误，停止该粒度归因 |
| 平均日消耗为 0 | 覆盖天数返回 `null`，另设 `infinite_coverage=true`，不存无穷大数值 |
| 无任何消耗记录 | 从首次入库日计算无消耗天数；首次入库也缺失时阻断 |
| 最近消耗晚于分析日期 | 日期异常，停止归因 |
| 单位成本缺失 | 可计算数量风险，但金额为 `null` 并标记不完整 |
| 单位成本为负 | 数据质量错误 |
| 分析窗口不足 | 返回实际覆盖天数及 `partial_window=true` |
| 只有调拨记录 | 调拨不重置有效消耗日期 |
| 新物料 | 从首次入库日起保护 30 天，不因历史不足直接判呆滞；首次入库缺失时阻断 |

## 5. 根因规则 v0.2

每个根因由确定性规则输出 `score`、`hits` 和 `evidence`。LLM 只能转述。

| 根因 | 必备证据 | 首版规则方向 |
|---|---|---|
| 需求下降 | 两个相邻窗口的有效需求/消耗 | 下降比例达到阈值加分 |
| 超量采购 | 到货量、剩余量、需求或消耗 | 采购形成的覆盖天数过高加分 |
| 生产延期 | 关联生产单、计划/实际开工日、状态、计划消耗数量 | 未关闭、延期超过阈值且当前仍有库存时加分 |

首版分数是候选原因排序依据，不解释为统计概率。若证据不足，结果必须明确显示 `insufficient_evidence`。

## 6. 用户故事

### US-01 风险清单

作为库存管理人员，我希望查询指定日期的高风险物料，以便优先处理占资金额高的库存。

验收要点：可按仓库和物料类别筛选；结果按呆滞金额排序；口径和分析日期可见。

### US-02 单物料归因

作为业务人员，我希望询问“为什么 MAT-SYN-001 库存积压”，以便看到指标、关联单据和候选原因。

验收要点：参数明确；结论有证据；无证据不强行归因。

### US-03 图关系追踪

作为分析人员，我希望查看物料与采购单、生产单和仓库的关系路径，以便核对跨单据影响。

验收要点：限制最大跳数和节点数；每条边带类型和来源标识；无路径返回 `empty`。

### US-04 降级分析

作为使用者，我希望在 LLM 不可用时仍获得结构化结果，以便核心业务分析不依赖模型在线状态。

验收要点：指标与规则结果完整；自然语言摘要可降级为模板。

## 7. MVP 默认与真实接入待确认项

MVP 默认：所有物料类别共用当前阈值；`SALES_ISSUE` 和 `PRODUCTION_ISSUE` 计为有效消耗；调拨和调整不重置有效消耗日期；安全库存、在途库存和质检冻结库存不单独建模；单位成本采用合成标准成本；同分根因按固定枚举顺序排序。

真实接入再确认：按物料类别配置阈值、退料/退货处理、安全/在途/冻结库存、企业成本口径、根因人工确认流程和建议动作审批策略。

## 8. 生产延期 MVP 口径

MVP 中 `ProductionOrder.material_id` 表示该生产计划准备消耗的一种物料，不引入 BOM 明细。延期天数按以下规则计算：

```text
actual_start 存在：delay_days = actual_start - planned_start
actual_start 为空：delay_days = as_of_date - planned_start
```

候选根因必须同时满足：当前库存大于 0、生产单状态为 `PLANNED`/`RELEASED`/`IN_PROGRESS`、计划消耗数量大于 0，且延期超过 `production_delay_days`。已按期关闭、没有计划消耗数量或无法关联当前物料时不得命中。

该规则只说明“生产延期可能导致计划消耗未发生”，不宣称统计因果关系，也不替代计划人员确认。

## 9. 公开口径参考

本项目没有照搬单一 ERP 的判定算法，只借鉴公开资料中的共同分析维度：

- SAP 的慢动/无动物料分析会关注“无消耗天数”、当前库存、最后使用日期和消耗/库存比率：<https://help.sap.com/docs/SAP_S4HANA_ON-PREMISE/91b21005dded4984bcccf4a69ae1300c/fa5bfb3a1b5f4547b980530de6abca9e.html>
- SAP 的库存周转分析将累计使用量与平均库存水平关联：<https://help.sap.com/docs/SAP_BUSINESS_ONE/68a2e87fb29941b5bf959a184d9c6727/932cbfc122f94afeae119a41f9d87f36.html>
- Oracle 的库存老化智能体使用周转次数、加权平均库龄和销售比例，并将调拨、跨组织转移或报废作为可能建议：<https://docs.oracle.com/en/cloud/saas/readiness/scm/26a/inv26a/26A-inventory-wn-f41414.htm>

这些资料也说明判定依赖配置和组织策略，因此文档中的 90/180 天只作为项目默认值，不宣称为行业统一标准。
