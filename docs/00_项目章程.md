# 项目章程

## 1. 项目身份

| 项目项 | 内容 |
|---|---|
| 中文名称 | 呆滞料智能体 |
| 英文名称 | Inventory Root-Cause Agent |
| 当前阶段 | Phase 0：项目准备 |
| 项目性质 | 个人作品集 / 企业 AI 应用工程实践 |
| 数据边界 | 仅使用项目自行生成的合成数据 |
| 首期形态 | 本地可运行的 FastAPI 服务 + 轻量演示页 |

## 2. 要解决的问题

库存人员通常需要回答三个递进问题：

1. 哪些“物料 × 仓库”组合已经呆滞或接近呆滞？
2. 库存为何形成：需求下降、采购过量，还是生产延期导致计划消耗未发生？
3. 结论依据是什么，下一步应该由谁核查或处置？

项目目标不是做一个能闲聊的机器人，而是做一条可复现的分析链：

```text
业务问题 -> 参数校验 -> 指标计算 -> 关系追踪 -> 规则归因 -> 证据校验 -> 回答
```

## 3. 用户与职责

| 角色 | 主要诉求 | MVP 输出 |
|---|---|---|
| 库存管理人员 | 找出高金额、高库龄物料 | 风险清单、排序和明细 |
| 采购人员 | 判断是否存在超量或过早采购 | 采购覆盖、到货与需求证据 |
| 计划/生产人员 | 排查生产延期或计划变化 | 关联生产单与延期证据 |
| 管理者 | 了解金额、根因分布与行动建议 | 汇总指标与可追溯报告 |

## 4. MVP 范围

### 包含

- 支持按物料、仓库、物料类别和分析日期筛选。
- 计算当前库存、库存金额、无消耗天数、平均日消耗、覆盖天数和风险等级。
- 识别三类候选根因：需求下降、超量采购、生产延期。
- 通过本地图结构追踪采购单、生产单、物料和仓库关系。
- 输出命中规则、证据字段、数据来源、计算口径和建议动作。
- 支持正常、有数据但无风险、无数据、数据异常和依赖失败等状态。
- 使用自动化测试和 Agent 评测集验证结果。

### 不包含

- 接入真实 ERP、客户数据库或公司内部平台。
- 自动执行报废、调拨、采购改单、订单关闭等写操作。
- 生产级多租户、权限中心、高并发和高可用集群。
- 训练或微调大模型。
- 用 LLM 自由生成数值、根因得分或证据。
- 销售取消、工程变更、供应商分析和真实 ERP 接入。
- 完整 BOM、工序、工作中心、生产领退料、物料预留和生产状态历史。
- 为堆技术栈而引入 Redis、消息队列或外部图数据库；只有出现真实需求后才扩展。

## 5. 成功标准

MVP 达成时，应能完成以下演示：

1. 查询某个合成物料，返回确定性的呆滞指标。
2. 追踪到至少一条关联业务路径，并解释根因得分。
3. 对相同数据库和分析日期重复执行，结构化结果一致。
4. 移除 LLM 配置后，仍返回指标与规则归因结果。
5. 对不存在的物料返回 `empty`，对数据库故障返回 `error`。
6. README 所列命令能在新环境中复现启动和测试。
7. 生产延期案例能够追溯到生产订单的计划日期、实际日期、状态和计划消耗数量。

详细验收条件见 `docs/03_验收标准.md`。

## 6. 关键约束

- 业务计算使用固定 `as_of_date`，禁止在领域逻辑中隐式读取当前时间。
- 阈值以配置对象传入，不散落为魔法数字。
- 证据只保存可核对的事实和工具执行摘要，不展示模型私有推理过程。
- 合成 ID 使用 `MAT-SYN-*`、`PO-SYN-*` 等明显标记。
- 项目文档中出现的业务规则是个人项目重新设计，不代表任何公司的真实规则。
- 生产订单采用公开、简化的合成模型，只表示某生产计划对一种物料的计划消耗，不模拟完整制造执行系统。

## 7. 里程碑

| 阶段 | 目标 | 退出条件 |
|---|---|---|
| Phase 0 | 需求、数据、验收与环境冻结 | 开工清单中的阻塞项已解决 |
| Phase 1 | 可运行的数据和后端 | 合成数据可重复生成，查询 API 通过测试 |
| Phase 2 | 指标与根因工具 | 规则和边界用例全部自动化验证 |
| Phase 3 | Agent 工作流 | 工具选择、降级和证据校验可运行 |
| Phase 4 | 评测与演示 | 评测报告、演示页和 2 分钟演示脚本完成 |
