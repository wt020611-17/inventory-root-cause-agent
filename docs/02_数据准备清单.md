# 数据准备清单

## 1. 数据原则

- 所有数据由固定随机种子生成，并标记为 `synthetic=true`。
- 每次生成记录 `dataset_version`、`seed` 和 `generated_at`。
- 同一版本和种子必须得到相同的业务事实。
- 测试断言依赖明确的场景标签，不依赖随机碰巧出现的结果。
- 禁止使用真实公司表名、字段名、客户名、单号规则或数值分布。

## 2. MVP 实体

| 实体 | 必要字段 | 关键校验 |
|---|---|---|
| `Material` | `material_id`, `name`, `category`, `unit_cost`, `created_date` | ID 唯一；成本非负 |
| `Warehouse` | `warehouse_id`, `name`, `region` | ID 唯一 |
| `InventoryMovement` | `movement_id`, `material_id`, `warehouse_id`, `movement_type`, `quantity`, `posted_at`, `source_doc_id` | 数量非零；引用存在；日期有效 |
| `PurchaseOrder` | `po_id`, `material_id`, `warehouse_id`, `ordered_qty`, `received_qty`, `planned_date`, `actual_date`, `status` | 收货量非负；状态枚举有效 |
| `ProductionOrder` | `production_order_id`, `material_id`, `warehouse_id`, `planned_consumption_qty`, `status`, `planned_start`, `actual_start`, `due_date`, `closed_at` | 数量非负；日期和状态组合可解释 |

MVP 固定为上述五个持久化实体。库存余额从流水聚合，不建 `InventorySnapshot`；图关系从业务外键构建，不建通用 `SourceDocumentLink`。销售单、ECN、供应商、BOM、工序和生产领退料均属于扩展范围。

## 3. 受控枚举

### 库存移动类型

- `PURCHASE_RECEIPT`
- `SALES_ISSUE`
- `PRODUCTION_ISSUE`
- `TRANSFER_IN`
- `TRANSFER_OUT`
- `ADJUSTMENT`

只有 `SALES_ISSUE` 和 `PRODUCTION_ISSUE` 计为有效消耗。退料、退货和生产入库不在 MVP 单独建模；需要时作为后续枚举扩展。

### 采购订单状态

- `PLANNED`
- `PARTIALLY_RECEIVED`
- `RECEIVED`
- `CANCELLED`

### 生产订单状态

- `PLANNED`
- `RELEASED`
- `IN_PROGRESS`
- `CLOSED`
- `CANCELLED`

### 数据状态

- `ok`：查询和计算成功且有数据。
- `empty`：执行成功但无匹配数据。
- `error`：执行失败。
- `blocked`：有数据，但质量问题阻止业务结论。

## 4. 必造场景

每个场景至少包含一个可独立断言的“物料 × 仓库”。

| 场景 ID | 预期风险 | 预期根因/行为 |
|---|---|---|
| `SYN-NORMAL-01` | 正常 | 有持续消耗，不归因为呆滞 |
| `SYN-DEMAND-DROP-01` | 慢动 | 需求显著下降 |
| `SYN-OVERBUY-01` | 慢动/无动 | 采购覆盖过高 |
| `SYN-PROD-DELAY-01` | 慢动 | 生产单延期 |
| `SYN-MULTI-CAUSE-01` | 无动 | 超量采购和生产延期并存并可排序 |
| `SYN-EMPTY-01` | 无结果 | 返回 `empty` |
| `SYN-BLOCKED-01` | 阻断 | 负库存或未来日期被识别 |

## 5. 数据质量检查

生成后必须自动执行：

1. 主键唯一性检查。
2. 外键引用完整性检查。
3. 状态和关系枚举检查。
4. 数量、金额非负与订单数量约束检查。
5. 日期顺序和分析日期越界检查。
6. 流水累计库存与查询结果一致性检查。
7. 采购单/生产单外键与图关系两端节点完整性检查。
8. 每个必造场景的预期标签覆盖检查。
9. 三类根因各至少有一个正例和一个反例。
10. 不存在真实企业标识、URL、凭据或疑似真实单号的扫描。

## 6. 数据规模

MVP 基线建议：

| 数据 | 基线规模 |
|---|---:|
| 物料 | 15～20 |
| 仓库 | 2 |
| 库存流水 | 300～600 |
| 采购单 | 20～30 |
| 生产单 | 15～25 |

规模不是首期目标。优先保证场景确定、链路闭合、结果可断言；性能数据集在功能基线通过后单独生成。
