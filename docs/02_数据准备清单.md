# 数据准备清单

## 1. 数据原则

- 所有数据由固定随机种子生成，并标记为 `synthetic=true`。
- 每次生成记录 `dataset_version`、`seed` 和 `generated_at`。
- 同一版本和种子必须得到相同的业务事实。
- 测试断言依赖明确的场景标签，不依赖随机碰巧出现的结果。
- 禁止使用真实公司表名、字段名、客户名、单号规则或数值分布。

## 2. MVP 实体

| 实体 | 必要字段 | 关键校验 |
|---|---|---|
| `Material` | `material_id`, `name`, `category`, `unit_cost`, `created_date` | ID 唯一；成本非负 |
| `Warehouse` | `warehouse_id`, `name`, `region` | ID 唯一 |
| `InventoryMovement` | `movement_id`, `material_id`, `warehouse_id`, `movement_type`, `quantity`, `posted_at`, `source_doc_id` | 数量非零；引用存在；日期有效 |
| `InventorySnapshot` | `material_id`, `warehouse_id`, `quantity`, `snapshot_date` | 粒度唯一；数量非负 |
| `PurchaseOrder` | `po_id`, `material_id`, `warehouse_id`, `ordered_qty`, `received_qty`, `planned_date`, `actual_date`, `status` | 收货量非负；状态枚举有效 |
| `ProductionOrder` | `production_id`, `material_id`, `planned_qty`, `status`, `planned_start`, `actual_start`, `due_date`, `closed_at` | 日期顺序可解释 |
| `SalesOrder` | `sales_id`, `material_id`, `ordered_qty`, `cancelled_qty`, `status`, `delivery_date` | 取消量不大于订单量 |
| `EngineeringChange` | `ecn_id`, `material_id`, `change_type`, `effective_date`, `replacement_material_id` | 替代关系不可自环 |
| `SourceDocumentLink` | `from_type`, `from_id`, `relation_type`, `to_type`, `to_id` | 两端存在；关系类型受控 |

首版建议使用库存流水作为计算事实，快照用于对账和查询加速。不能只造快照，否则无法可靠计算最后消耗日期和库龄。

## 3. 受控枚举

### 库存移动类型

- `PURCHASE_RECEIPT`
- `PRODUCTION_RECEIPT`
- `SALES_ISSUE`
- `PRODUCTION_ISSUE`
- `TRANSFER_IN`
- `TRANSFER_OUT`
- `RETURN_IN`
- `RETURN_OUT`
- `ADJUSTMENT`

### 工程变更类型

- `REPLACED`
- `DISCONTINUED`
- `REVISION_CHANGED`

### 数据状态

- `ok`：查询和计算成功且有数据。
- `empty`：执行成功但无匹配数据。
- `error`：执行失败。
- `blocked`：有数据，但质量问题阻止业务结论。

## 4. 必造场景

每个场景至少包含一个可独立断言的“物料 × 仓库”。

| 场景 ID | 预期风险 | 预期根因/行为 |
|---|---|---|
| `SYN-NORMAL-01` | 正常 | 有持续消耗，不归因为呆滞 |
| `SYN-DEMAND-DROP-01` | 慢动 | 需求显著下降 |
| `SYN-OVERBUY-01` | 慢动/无动 | 采购覆盖过高 |
| `SYN-PROD-DELAY-01` | 慢动 | 生产单延期 |
| `SYN-SALES-CANCEL-01` | 慢动 | 销售订单大量取消 |
| `SYN-ECN-01` | 无动 | 旧料被替代或停用 |
| `SYN-MULTI-CAUSE-01` | 无动 | 至少两类根因并存并可排序 |
| `SYN-TRANSFER-01` | 慢动 | 只有调拨，不应重置有效消耗日 |
| `SYN-NEW-MATERIAL-01` | 正常/观察中 | 新物料保护期生效 |
| `SYN-EMPTY-01` | 无结果 | 返回 `empty` |
| `SYN-BAD-NEGATIVE-01` | 阻断 | 负库存被识别 |
| `SYN-BAD-DATE-01` | 阻断 | 未来消耗日期被识别 |

## 5. 数据质量检查

生成后必须自动执行：

1. 主键唯一性检查。
2. 外键引用完整性检查。
3. 状态和关系枚举检查。
4. 数量、金额非负与订单数量约束检查。
5. 日期顺序和分析日期越界检查。
6. 流水累计库存与快照库存对账。
7. 图关系两端节点完整性检查。
8. 每个必造场景的预期标签覆盖检查。
9. 每类根因至少有一个正例和一个反例。
10. 不存在真实企业标识、URL、凭据或疑似真实单号的扫描。

## 6. 数据规模

MVP 基线建议：

| 数据 | 基线规模 |
|---|---:|
| 物料 | 100 |
| 仓库 | 3 |
| 库存流水 | 5,000～10,000 |
| 采购单 | 300 |
| 生产单 | 300 |
| 销售单 | 500 |
| ECN | 30 |

规模不是首期目标。优先保证场景确定、链路闭合、结果可断言；性能数据集在功能基线通过后单独生成。
